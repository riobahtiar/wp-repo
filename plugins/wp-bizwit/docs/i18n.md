# Internationalisation (i18n)

WP BizWit follows official WordPress guides for **PHP and JavaScript**:

| Layer | Guide |
|-------|--------|
| PHP | [How to Internationalize Your Plugin](https://developer.wordpress.org/plugins/internationalization/how-to-internationalize-your-plugin/) |
| JavaScript | [Gutenberg: Internationalization](https://github.com/WordPress/gutenberg/blob/trunk/docs/how-to-guides/internationalization.md) |

## Rules (non-negotiable)

1. **Source language is English.** Every `__()` / `esc_html_e()` / JS `__()`
   string uses an English *msgid*. Never put Bahasa Indonesia in the source
   string just because Indonesia is the primary market.
2. **Text domain is `wp-bizwit`.** Domain path `/languages` (plugin header).
3. **Indonesian ships complete** in `languages/wp-bizwit-id_ID.po` (+ compiled
   `.mo` / `.l10n.php` / script `.json` at release).
4. **Switching the site language must switch the UI** (en_US ↔ id_ID). No mixed
   screens.
5. **Region ≠ language.** `Localization\Indonesia` still controls NPWP fields
   and rupiah rules when the UI is English. Labels still go through gettext.

### Domain terms (OK in both languages)

NPWP, NIB, NIK, PKP, PPN, PPh, SPK, BAST, SP2D, QRIS, UMKM, RT/RW, kelurahan,
kecamatan, satker, terbilang, bea meterai, kwitansi, faktur (as document names).

## JavaScript (Gutenberg pattern)

Exactly as in the Gutenberg how-to:

### 1. Import from `@wordpress/i18n`

```js
import { __ } from '@wordpress/i18n';

__( 'Hello World', 'wp-bizwit' );
_n( '%s item', '%s items', count, 'wp-bizwit' );
_x( 'Post', 'noun', 'wp-bizwit' );
```

Optional re-export: `import { __ } from '@/app/i18n'` (same package).

### 2. Do not bundle a second copy of i18n

Vite **externalizes** `@wordpress/i18n` → runtime global `wp.i18n` (same idea as
`@wordpress/dependency-extraction-webpack-plugin` in Gutenberg). WordPress core
provides the implementation via the `wp-i18n` script handle.

### 3. PHP: dependency + script translations

```php
wp_enqueue_script(
    'wp-bizwit-dashboard',
    $url,
    array( 'wp-i18n' ), // required
    $version,
    true
);

// Optional third argument = path to shipped JSON (not only translate.wordpress.org).
wp_set_script_translations(
    'wp-bizwit-dashboard',
    'wp-bizwit',
    plugin_dir_path( __FILE__ ) . 'languages'
);
```

Implemented in `src/Admin/Assets.php` for every Vite entry.

Handles use **hyphens** (`wp-bizwit-dashboard`), not slashes, so JSON filenames
`wp-bizwit-id_ID-wp-bizwit-dashboard.json` are valid.

### 4. Ship Jed 1.x JSON

```bash
# After updating the .po:
npm run -w wp-bizwit i18n:compile
# runs make-mo, make-php, and scripts/build-script-translations.mjs
```

`build-script-translations.mjs` writes handle-based (and source-path md5) JSON
files under `languages/`, matching what `wp_set_script_translations()` loads.

## PHP

```php
__( 'Budget', 'wp-bizwit' );
esc_html_e( 'Save settings', 'wp-bizwit' );

// Region may override labels; fallback is still a gettext string:
$region->field_label( 'budget', __( 'Budget', 'wp-bizwit' ) );
```

Load textdomain on `init` (not in the plugin constructor) so the active locale
is applied — see `WP_BizWit::load_textdomain()`.

## Files

| File | Role |
|------|------|
| `languages/wp-bizwit.pot` | Template (English msgids) |
| `languages/wp-bizwit-id_ID.po` | Indonesian translations |
| `languages/wp-bizwit-id_ID.mo` | PHP runtime (compiled) |
| `languages/wp-bizwit-id_ID.l10n.php` | PHP array loader (compiled) |
| `languages/wp-bizwit-id_ID-wp-bizwit-*.json` | Script translations (Jed) |
| `src/I18n/Script_Strings.php` | Ensures JS strings appear in the pot |
| `resources/app/i18n.ts` | Re-export of `@wordpress/i18n` |
| `vite.config.ts` | Externalizes `@wordpress/i18n` → `wp.i18n` |

## Workflow after adding strings

**A feature that adds user-facing copy is not done until step 5 passes.**

```bash
cd plugins/wp-bizwit   # or from monorepo: npm run -w wp-bizwit …

# 1–2. Extract English msgids and merge into Indonesian catalogue
npm run i18n:sync
#    (= i18n:pot && i18n:update-po && i18n:check-id)
#    Step 2 will FAIL if any msgstr is still empty — that is intentional.

# 3. Translate every new/empty msgid in languages/wp-bizwit-id_ID.po

# 4. Re-check (must exit 0)
npm run i18n:check-id

# 5. Compile PHP + Jed JSON for scripts
npm run i18n:compile
```

| Script | Purpose |
|--------|---------|
| `i18n:pot` | Build English template from PHP + JS |
| `i18n:update-po` | Merge pot into `wp-bizwit-id_ID.po` |
| `i18n:check-id` | **Gate:** fail if any Indonesian `msgstr` is empty or fuzzy |
| `i18n:sync` | pot + update-po + check-id (use after adding strings) |
| `i18n:compile` | `.mo` + `.l10n.php` + script JSON |

Use the **global** `wp` binary (Composer’s `vendor/bin/wp` lacks the i18n pack).

## Verify both languages

```bash
wp language core install en_US
wp site switch-language en_US
# Clients, Projects, Settings, Dashboard Vue pilot → English UI

wp language core install id_ID
wp site switch-language id_ID
# Same screens → Indonesian UI; NPWP / PKP / termin unchanged as domain terms
```

Hard-refresh so CSS/JS hashes reload.

## Common mistakes

| Mistake | Result |
|---------|--------|
| Indonesian text as `__()` source | English site still shows Indonesian |
| Hardcoded Vue strings (no `@wordpress/i18n`) | Never translates |
| Bundling `@wordpress/i18n` into the Vite chunk | Two i18n runtimes; translations may not apply |
| Missing `wp-i18n` script dependency | `wp.i18n` undefined at runtime |
| Missing `wp_set_script_translations` | Jed JSON never loads |
| Script handle with `/` | Handle-based `.json` filename becomes a path |
| `__()` only, no `id_ID` msgstr / no compile | **Mixed EN/ID UI** — the bug this gate prevents |
| Calling “done” after code without `i18n:check-id` | Same mixed-language screens in production |

## Definition of done (i18n)

Before reporting a UI feature complete:

1. [ ] Every user-facing string uses `__()` / `esc_html_e()` / JS `__()` (`wp-bizwit`)
2. [ ] `npm run i18n:sync` (or pot + update-po)
3. [ ] All new msgids have Indonesian `msgstr` in `wp-bizwit-id_ID.po`
4. [ ] `npm run i18n:check-id` exits **0**
5. [ ] `npm run i18n:compile`
6. [ ] Spot-check the screen with site language **id_ID** (no English leftovers)
